## Writing segment

Start with the claim, interpretation, and exhibit. Ask the agent to identify missing evidence before drafting. Distinguish the task prompt, persistent author instructions, response style, and reusable skill.

The author rules come from Tomas's own academic-draft-editing, econ-write, and humanizer skills and his directions in the call. They emphasize an economic argument for the intended reader, established terms, necessary and defined notation, faithful claims, and prose that does not reveal internal editing history. The paragraph example is synthetic and contains no empirical estimate. Its revision removes an unsupported claim rather than manufacturing a result.

The CuposBEA slide reproduces three exact sentences from an author-requested figure placeholder. It retains units, common samples and smoothing, weighting, and support restrictions. It omits the surrounding draft, results, model notation, and private path. The rendered teaching excerpt is explicitly labeled as typeset, not a screenshot of the private manuscript.

The synthetic figure/table brief names the population, denominator, axes, units, table entries, verification, and deliverables. It also states which choices the author must settle before computation. This distinction is part of the lesson: precision includes recognizing an unresolved scientific decision.

Matt Pocock's grill-me is an interview workflow; grill-with-docs adds repository domain documentation and decisions. The paper-interview prompt is our adaptation. Installation instructions preserve dependencies and distinguish plugin installation from copied skills. No third-party skill was installed. The expanded detector section was omitted following the author's latest direction.

## Twenty-five-minute revision demonstration

1. Minutes 0–4: inspect a permitted comment set. Distinguish errors to investigate from scientific decisions and stylistic suggestions. A reviewer's assertion is evidence to check, not an established fact.
2. Minutes 4–12: draft issues grouped by argument and affected files. Identify dependencies, owners, acceptance criteria, inputs, and outputs. Show the synthetic issue example if a private case has not been cleared.
3. Minutes 12–18: show independent agents working on separable tasks. Reconcile a mathematical or interpretive disagreement and inspect the reference check. Sequence edits that depend on the same scientific decision.
4. Minutes 18–23: inspect a verified exhibit, candidate PR diff, and integration plan. Rebuild affected outputs from the same input version.
5. Minutes 23–25: inspect the LaTeX diff and compiled draft. Revisit the original comments and explain what is resolved, what was declined with reasons, and what remains open.

Prepare source versions, small reference checks, and clearly labeled fallback checkpoints. State whether each output is prepared or produced live. This preparation creates no hosted issue, PR, assignment, email, or publication. A live demonstration involving those actions requires the author's separate direction and a suitable teaching destination.

## Candid assessment

The new writing segment supplies the concrete author decisions missing from the first revision. The Refine-to-revision arc also connects math, code, exhibits, and drafting more naturally than a README edit.

The main unresolved weakness is the scientific demonstration. A workflow diagram cannot substitute for a chosen case, a correct small reference check, and a rehearsed sequence. Twenty-five minutes can show a prepared revision process; it cannot credibly promise a new model, estimator, validated findings, and finished paper from scratch.

The comparison remains dense. Spend most of its ten minutes on instructions, skills, planning, and review. Remote control, advisor, install details, and policy-dependent interfaces should be optional.

The 18-minute writing segment supports discussion but not a separate long exercise. If participants need hands-on writing, use a six-minute paired edit within that segment and reduce the worked explanation. A separate 15–20-minute exercise requires cutting another segment, not adding slides to this plan.

The orchestration segment is a debrief of the live demonstration. Nine minutes would be too short if all its concepts were introduced there for the first time. Keep the task board visible during the earlier work.

The generic Command Center illustration remains sufficient. An actual private dashboard screen still needs the author's approval of what will be shown.
